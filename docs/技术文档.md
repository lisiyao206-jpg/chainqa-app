## 2. 后端架构

### 2.1 入口与路由

后端是单文件 `server.mjs`，使用 Node.js 原生 `http` 模块，**无第三方框架依赖**。按「请求方式 + 网址」分发：

```
GET  /api/*         → 数据 API（所有内置模块）
GET  /               → 前端单页应用（web/dist/index.html）
GET  /public/*       → 静态资源
```

所有 API 请求都经过 `withUser(req, res, { admin: false })` 认证，管理员接口另需 `withUser(..., { admin: true })`。

### 2.2 核心模块

| 模块 | 职责 |
|---|---|
| `db.mjs` | SQLite 建表、表结构迁移、22 张表 |
| `auth.mjs` | 注册、登录、token 认证、密码 scrypt 加盐哈希 |
| `rag.mjs` | 教材切片、向量化、相似度检索、流式生成 |
| `agent.mjs` | 审计 Agent，函数调用工具：scan/lookup/search |
| `scanner.mjs` | 规则扫描 + SWC 漏洞库（14 种） |
| `variant.mjs` | AI 出题、规则验题、缓存复用 |
| `data.mjs` | 笔记、错题、关卡进度、审计记录 CRUD |
| `admin.mjs` | 管理员后台：用户管理、登录记录、问答日志、反馈 |
| `social.mjs` | 好友、聊天室、广场、点赞、收藏 |
| `quiz.mjs` | 防御战 AI 出题 |
| `safety.mjs` | AI 注入检测、内容审核、私钥保护 |

## 3. 数据库设计

共 **22 张表**，按业务分为四组：

| 分组 | 表 |
|---|---|
| 账号 | `users`、`sessions`（登录凭证）、`login_logs`、`sms_codes` |
| 学习 | `notes`（笔记）、`mistakes`（错题）、`game_progress`（关卡进度）、`camp_progress`（防御战记录）、`audit_records`（审计记录）、`variants`（变种题库） |
| 社区 | `friend_requests`、`friends`、`rooms`、`members`、`messages`、`files`、`posts`、`likes`、`collections`、`comments` |
| 运营 | `qa_logs`（问答日志）、`feedback`（反馈） |

**去重与优化设计**：
- `game_progress` 用联合主键保证「一人一关一条记录」，保存时用 `ON CONFLICT … DO UPDATE SET star = MAX(…)` 只保留最好成绩
- `mistakes` 按 `(user_id, question)` 去重，一道错题只记一次并累计错误次数
- `audit_records` 按代码指纹去重（同一合约不重复记录）
- 外键 `ON DELETE CASCADE`：删除用户时，其数据一并清除

## 4. AI 集成

### 4.1 智谱 AI 模型

| 模型 | 用途 |
|---|---|
| `glm-4-flash` | 问答、AI 审计 Agent、出题、思维导图 |
| `glm-4v-flash` | 截图识别代码 |
| `embedding-3` | 文本向量化（知识库检索） |

### 4.2 RAG 问答（白帽导师）

```
用户提问
  ↓
embedding-3 转向量
  ↓
与 900+ 教材片段计算余弦相似度
  ↓
相似度 < 0.45：拒答「知识库中未找到相关依据」
  ↓
相似度 ≥ 0.45：把片段 + 问题 + 规则交给 glm-4-flash
  ↓
要求只依据资料回答并标注 [1][2]
  ↓
SSE 流式推送前端，逐字显示 + 引用原文
```

**防幻觉三件套**：提示词限定只依据资料 + 相似度阈值过滤 + 引用编号可核对。

### 4.3 AI 审计 Agent

审计 Agent 具备工具调用能力：

| 工具 | 作用 |
|---|---|
| `scan` | 规则扫描合约，返回疑似漏洞 |
| `lookup_swc` | 查询 SWC 漏洞库 |
| `search` | 检索教材知识库 |

Agent 会自主规划步骤：先扫描发现漏洞 → 查 SWC 漏洞库了解原理和修复方法 → 检索教材确认知识点 → 最后输出带出处的审计报告。
