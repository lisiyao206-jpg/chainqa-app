# 区块链 + 电子存证：为什么法院认可链上的证据

## 这一章要做什么

前面的路线讲了区块链「怎么做到改不了」。这一章看它在现实中最早被大规模使用的场景之一：**电子存证**。

我们会先看一个真实的问题，再看我国法院的规定是怎么写的，最后亲手部署一个最小的存证合约，体验「存证 → 核验」的全过程。

## 一个真实的问题：网上的证据怎么证明没被改过

假设你写了一篇原创文章发到网上，过了几天发现被别人整篇搬走。你去维权，需要证明两件事：

1. 这篇文章**在某个时间点就已经存在**，而且是你的；
2. 你拿出来的这份文件，**和当时的一模一样，没有被改过**。

截图、聊天记录、网页这类电子数据，复制和修改都很容易，对方很可能会说「这是你后来改的」。传统做法是请公证处做公证，但费用和时间成本都不低。

区块链正好擅长解决第 2 点：数据写进区块后，任何改动都会让哈希对不上，而且账本由多个节点共同保存，单独一方改不了。

## 法院是怎么规定的

这不只是技术上的说法，我国法院已经在司法解释里明确了区块链存证的效力：

| 时间 | 文件 | 规定的要点 |
| --- | --- | --- |
| 2018 年 9 月 | 《最高人民法院关于互联网法院审理案件若干问题的规定》第十一条 | 当事人提交的电子数据，通过电子签名、可信时间戳、哈希值校验、**区块链**等证据收集、固定和防篡改的技术手段，或者通过电子取证存证平台认证，能够证明其真实性的，互联网法院应当确认 |
| 2021 年 8 月起施行 | 《人民法院在线诉讼规则》第十六条 | 当事人作为证据提交的电子数据系通过区块链技术存储，并经技术核验一致的，人民法院**可以认定该电子数据上链后未经篡改**，但有相反证据足以推翻的除外 |

> 两份文件的原文见本章末尾的「参考资料」。

## 一个容易忽略的细节：上链前 ≠ 上链后

注意第十六条的用词：法院可以认定数据**「上链后」**未经篡改。

区块链能保证的是：**从写上链那一刻起，数据没有被改过**。至于写上链之前，这份数据本身是不是真的、是不是当事人自己伪造的，区块链管不了。《人民法院在线诉讼规则》第十六条至第十九条对区块链存证作了专门规定，就包括了对上链前数据真实性的审查。

所以，区块链存证不是「上了链就一定是真的」，而是把「这份数据从某个时刻起没有被改过」这件事，变得可以被核验。

## 为什么链上只存「指纹」

存证时，一般**不会把文件原文放到链上**，而是只放文件的**哈希值**（指纹）：

- 原文可能很大（视频、合同扫描件），全部上链成本很高；
- 原文可能涉及隐私或商业秘密，不适合让链上所有节点都看到；
- 哈希值长度固定、很小，而且能唯一对应原文：原文改一个字，哈希就完全不同（见区块链基础 P02 一章）。

核验时，把手里的文件重新算一次哈希，和链上记录的比一比：**一致，就说明文件和存证时一模一样。**

## 动手：部署一个存证合约

本章附带了一个很小的合约 `HashNotary.sol`，点页面上的「在合约练习场打开」就能载入：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract HashNotary {
    struct Record {
        address owner;
        uint256 time;
        uint256 blockNo;
    }

    mapping(bytes32 => Record) private records;

    function hashOf(string memory text) public pure returns (bytes32) {
        return keccak256(bytes(text));
    }

    function notarize(bytes32 hash) public {
        require(records[hash].time == 0, "already notarized");
        records[hash] = Record(msg.sender, block.timestamp, block.number);
    }

    function verify(bytes32 hash) public view returns (bool exists, address owner, uint256 time, uint256 blockNo) {
        Record memory r = records[hash];
        return (r.time != 0, r.owner, r.time, r.blockNo);
    }
}
```

操作步骤：

1. 编译、部署到链上；
2. 调用 `hashOf`，输入一句话，比如 `我的原创文章 v1`，得到一串 0x 开头的指纹，复制下来；
3. 调用 `notarize`，粘贴这个指纹，发送交易，存证完成；
4. 调用 `verify`，粘贴同一个指纹：会返回 `true`、你的账户地址、存证时间和区块号；
5. 再用 `hashOf` 算一下 `我的原创文章 v2`（只改了一个字），拿新指纹去 `verify`：返回 `false`，说明这份「改过的文件」没有存过证；
6. 再对原来的指纹调用一次 `notarize`：交易会被拒绝（`already notarized`），同一份文件不能被别人「抢先」重新存证。

## 小结

- 区块链存证的核心，是把文件的**哈希值**写上链，用来证明文件从某个时刻起没有被改过；
- 我国法院在 2018 年的互联网法院规定和 2021 年的《人民法院在线诉讼规则》中，都明确了区块链存证的效力；
- 区块链只能证明数据**上链后**未被篡改，上链前的真实性仍需要单独审查；
- 只存指纹、不存原文，既节省成本，又保护隐私。
