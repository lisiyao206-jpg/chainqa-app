# 系统架构说明

> 面向评审的「一页纸」架构说明：系统干了什么、怎么做的、为什么这样设计。

---

## 一句话总结

**链知答 LIANZHIDA** 是一个“智能合约安全审计学习与实践平台”：学员读教材可以问 AI 导师（带出处的 RAG 问答），完成章节后参与防御战（AI 出题、规则验题），对抗漏洞怪兽（10 关 3D 试炼），最后用审计 Agent 检查真实合约。整个系统把“学习、练习、审计”做成一条龙闭环。

## 核心模块与职责

| 模块 | 职责 | 关键设计 |
|---|---|---|
| `rag.mjs` | 文本切片、向量化、相似度检索、流式生成 | 900 字符切片、余弦相似度、阈值拒答 |
| `agent.mjs` | AI 审计 Agent | 工具列表：`scan`/`lookup`/`search`，自主规划步骤 |
| `scanner.mjs` | 规则扫描 + SWC 漏洞库 | 14 个 SWC 漏洞类型，多模式正则匹配 |
| `variant.mjs` | AI 变种出题 | AI 出题 → 规则扫描器自动验题 → 缓存复用 |
| `data.mjs` | 数据持久化 | 笔记、错题、关卡进度、审计记录 |
| `safety.mjs` | AI 安全 | 注入检测、内容审核、私钥保护 |
| `mcp-server.mjs` | MCP 服务 | JSON-RPC 2.0 stdio，3 个工具对外开放 |

## RAG 问答流程（白帽导师）

```
用户提问
  ↓
embedding-3 将问题向量化
  ↓
与 900+ 教材片段计算余弦相似度，取 top-K（默认 4）
  ↓
相似度低于阈值（0.45）：拒答「未找到相关依据」
  ↓
高于阈值：把片段 + 规则交给 glm-4-flash，要求只依据资料回答并标注 [1][2]
  ↓
SSE 流式推送前端，逐字显示 + 引用原文
```

**防幻觉三件套**：
1. 提示词限定「只依据资料回答」
2. 相似度阈值过滤不相关资料
3. 回答带引用编号，用户可点开核对原文

## 实战任务（试炼对战）流程

```
用户选关（10 关，每关 1 只怪兽）
  ↓
AI 出 4 道变种题（variant.mjs）
  ↓
规则扫描器自动验题（无论 AI 怎么出，规则库验，确保题一定可解）
  ↓
用户两回合对战：锁定弱点 → 修补漏洞
  ↓
后端校验修补结果，更新关卡进度（星星 + 勋章）
```

## 安全与隐私

- 密钥只放在后端 `.env`，不进前端代码，也不提交到 Git
- 密码使用 scrypt 加盐哈希，数据库只存 `盐:哈希`
- 所有 SQL 都使用 `?` 参数占位符，防注入
- 每条数据操作带 `WHERE user_id = ?`，数据隔离
- 管理员权限在后端校验，非管理员返回 403
- 防路径穿越：读取文件时检查路径，不允许 `../`
- AI 安全：注入检测、内容审核、私钥/助记词保护
