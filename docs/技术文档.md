## 3. 区块链集成

### 3.1 联盟链

1. 使用 FISCO BCOS 官方 `build_chain.sh` 搭建：`bash build_chain.sh -l 127.0.0.1:4 -p 30300,20200,8545`，单机 4 节点、1 个群组、PBFT 共识
2. 通过 WeBASE-Front 的 HTTP 接口接入（`chain.mjs`）：`/contract/deploy` 部署、`/trans/handle` 发交易 / 只读调用、`/privateKey` 管理账户、`/web3/blockNumber` 查区块高度
3. 每个用户在练习场有独立的链上账户（`playground_<用户 id>`）；实验场使用管理员、新管理员、攻击者三个固定账户

### 3.2 现场编译（`solidity.mjs`）

| 情况 | 处理 |
|---|---|
| `pragma` 是 0.4～0.6 | 用 solc 0.6.10（FISCO BCOS v2 官方支持的最高版本） |
| `pragma` 是 0.7 / 0.8 | 用 solc 0.8.38，`evmVersion` 设为 `byzantium`，生成的字节码只用老指令，FISCO BCOS v2 的虚拟机可以执行（2026-11-10 在本链实测：部署、调用、0.8 溢出检查、`unchecked` 均正常） |
| `import "@openzeppelin/contracts/..."` | 从后端安装的 OpenZeppelin 5.0.2 读取 |
| `import` 教材其他章节的合约 | 在 `knowledge/WTF-Solidity/<章节>/` 中查找，检查路径防止越界 |
| 其他 import | 拒绝，并给出中文说明 |

用 WTF-Solidity 教材中 73 个带合约的章节统计：**64 个可直接编译部署**。其余 9 个依赖新版虚拟机指令（`create2` 的 salt、`chainid`）或外部库（Chainlink、forge-std），在练习场中不可用，属于已知限制。

### 3.3 链上实验场（`lab.mjs` + `chainlab/labs.mjs`）

```
学生提交代码
  → 检查必需函数没被删改 → 编译（失败则返回行号和中文说明）
  → 对每一项检验：重新部署一份学生的合约
       业务检验：管理员存入、取出、交接，必须全部成功
       攻击检验：攻击者伪造存款 / 直接搬空 / 篡位夺权
  → 每笔交易实时通过 SSE 推送到页面（区块号、交易哈希、成功 / 被拒原因）
  → 判定：全部攻击被挡住且业务正常才算通过；未通过的项目给出「去哪里找问题」的提示
  → 记录尝试次数；失败 3 次后可查看参考答案
```

### 3.4 合约练习场（`playground.mjs`）

1. 编辑器 → 编译 → 选择合约、填构造参数 → 部署 → 按「状态 / 查询 / 交易」三组调用函数
2. 调用前在后端检查每个参数的格式（uint、address、bool、bytesN），用中文指出哪一个填错
3. 同一用户同一时间只能有一个写操作；部署和交易每分钟最多 20 次，只读查询每分钟最多 120 次
4. 从教材打开时，自动把本章附带的 .sol 文件按依赖顺序合并载入

### 3.5 FISCO BCOS 与以太坊的差异

实测发现 FISCO BCOS 的 `block.timestamp` 以**毫秒**为单位（以太坊为秒），按以太坊写的时间逻辑会相差 1000 倍。该问题已写成教材 F02 章，附带验证合约。

## 4. AI 集成

### 4.1 模型

| 模型 | 用途 |
|---|---|
| `glm-4-flash` | 白帽导师问答、审计 Agent、防御战出题、思维导图、学习建议 |
| `glm-4v-flash` | 截图识别代码 |
| `embedding-3` | 教材片段与问题向量化 |

### 4.2 RAG 问答（白帽导师）

```
用户提问 → 注入检测（safety.mjs）
  → embedding-3 向量化 → 与教材片段（每段约 900 字）算余弦相似度，取前 4 段
  → 最高相似度 < 0.45：拒答「知识库中未找到相关依据」
  → 否则：片段 + 问题 + 规则交给 glm-4-flash，要求只依据资料、标注 [1][2]
  → SSE 流式输出，附可展开的引用原文；问答写入 qa_logs 供后台审查
```

阈值 0.45 由 `eval/` 对照实验确定：教材内 20 题最高相似度均 ≥ 0.538，教材外 10 题均 ≤ 0.421。对照结果：准确度 97 vs 85，超纲拒答率 100% vs 30%（详见 `docs/评测报告.md`）。

### 4.3 AI 审计 Agent（`agent.mjs`）

函数调用模式，工具：`scan_contract`（规则扫描）、`lookup_swc`（SWC 漏洞库，15 类）、`search_knowledge`（教材检索）。Agent 自主规划调用顺序，最多 6 轮，每一步实时显示；同一份工具也通过 `mcp-server.mjs` 以 MCP 协议开放给外部 AI 编程助手。

### 4.4 学习报告（`report.mjs`）

16 个知识点，每章教材、每个关卡、每个链上实验都标注了所考的知识点（`knowledge.mjs`）。报告综合防御战成绩、关卡星级、实验通过情况和错题来源，计算每个知识点的掌握度，推荐下一步学习内容；AI 学习建议基于这些统计数据生成。老师端按班级汇总，可查看每个学生的报告。

## 5. 教材与内容质量

| 路线 | 来源 | 章数 |
|---|---|---|
| 01 区块链基础 | 自编，对照 ethereum.org、FISCO BCOS 官方文档 | 7 |
| 02 联盟链 FISCO BCOS 实战 | 自编，含平台实测数据 | 1 |
| 03 智能合约开发 | WTF-Solidity | 57 |
| 04 智能合约安全 | WTF-Solidity | 17 |
| 05 区块链应用与前沿 | 自编：电子存证（最高人民法院司法解释）、供应链金融（人民银行等八部门意见） | 2 |

质量保障：
1. 自编章节的结论都附官方出处；带合约的章节附 .sol 文件，并在链上实测过
2. 外链经服务器逐一实测：国内可访问的显示为蓝色链接，无法访问的改为灰色文字并保留出处
3. 每章末尾有纠错入口（内容有误 / 讲得不清楚 / 链接打不开 / 代码跑不通 / 建议补充），管理员在后台「教材纠错」中集中处理并回复

## 6. 数据库设计

SQLite，共 28 张表：

| 分组 | 表 |
|---|---|
| 账号 | `users`、`sessions`、`login_logs`、`sms_codes`、`app_secrets` |
| 学习 | `notes`、`mistakes`、`game_progress`、`camp_progress`、`audit_records`、`lab_progress` |
| 班级 | `classes`、`class_members`、`class_tasks`、`task_reviews`、`class_materials` |
| 社区 | `friend_requests`、`friends`、`rooms`、`room_members`、`messages`、`files`、`posts`、`post_likes`、`post_favorites`、`post_comments` |
| 运营 | `qa_logs`、`feedback` |

1. 外键 `ON DELETE CASCADE`：删除用户时其数据一并清除
2. `game_progress` 联合主键，`ON CONFLICT … DO UPDATE SET star = MAX(…)` 只保留最好成绩
3. 错题按题目去重并累计错误次数，`ref` 字段记录出处（章节或关卡），用于按知识点统计
4. 匿名帖子 / 评论只存 `anonymous` 标记；展示时的代号由服务器随机密钥对「帖子 id + 用户 id」做 HMAC 得出：同一帖内代号固定，跨帖不同，无法反推身份；只有管理员能看到真实作者
5. 表结构通过 `ALTER TABLE … ADD COLUMN` 迁移，旧数据库升级后数据保留

## 7. 安全

| 方面 | 措施 |
|---|---|
| 密钥 | API Key 只在后端 `.env`；`.env`、数据库、上传文件、向量库均在 `.gitignore` 中 |
| 账号 | scrypt 加盐哈希；改密码需验证旧密码；验证码 60 秒限发、5 分钟有效、输错 5 次作废 |
| 数据 | SQL 全部参数化；每次数据操作校验 `user_id`；管理员接口后端校验角色 |
| 文件 | 读教材 / 合约 / import 时检查路径防穿越；上传文件扩展名白名单、大小限制 |
| 链上 | 节点以 127.0.0.1 组网，WeBASE 与节点端口不对外开放；写操作串行 + 限流；合约代码长度上限 |
| AI | 提示词注入检测、内容审核；私钥 / 助记词防泄露（区分私钥与交易哈希） |

## 8. 部署

| 组件 | 方式 |
|---|---|
| 服务器 | 腾讯云轻量应用服务器，Ubuntu 22.04，2 核 4G，公网 IP 访问 |

| 反向代理 | nginx：80 → 127.0.0.1:3000，开启 gzip，静态资源缓存 30 天，关闭 SSE 缓冲 |
| 更新 | `git pull` → `cd web && npm run build` → `sudo systemctl restart chainqa` |

## 9. 已知限制与后续计划

1. 练习场不支持依赖 `create2` salt / `chainid` 的合约（FISCO BCOS v2 虚拟机限制），后续可升级到 FISCO BCOS v3
2. 链上实验场目前上线 1 道题（金库权限），其余 9 道与漏洞猎人关卡对应，陆续开放
3. 注册时填写的手机号暂未做短信验证（未开通短信服务），后续接入
4. 第 02、05 路线的自编教材继续扩充（跨链、隐私计算等）
